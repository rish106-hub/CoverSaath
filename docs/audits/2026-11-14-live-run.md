### Bug found and fixed: unknown Sarvam layout tag blocks every document

Live Sarvam output carries the layout tag `reference`, which was not in `OCR_BLOCK_TAGS`. Validation failed the whole OCR job, so **no holding was ever created for any document**. Stub tests never produce that tag. Fix on this branch:

- `reference` added to `OCR_BLOCK_TAGS` (`src/features/input/ocr-blocks.js`).
- The Sarvam adapter maps any tag it does not know to `null` (text kept, layout hint dropped), so a new provider tag cannot block ingestion again (`sarvamLayoutTag` in `src/integrations/sarvam/doc-ai-transport.js`).
- `tests/sarvam-layout-tags.test.mjs`: adapter list equals the stored-block contract; unknown tags become null and keep text.

## What this means for a user

Fact reading from a real OCR result is good. Answering is not yet trustworthy: a confident wrong answer about cover or a claim loses a user for good. Priority order agreed with the owner's end-user framing:

1. **Trust**: chat says "your policy does not say this, see page X" when no clause or fact answers the exact question; answers quote the clause, not the page. Target 0 invented answers, then raise correctness.
2. **First value in 60 s**: after upload, a card of the terms that cost money, computed by code (room-rent proportionate deduction example, co-pay, deductible, PED wait end date from the policy start, sub-limits).
3. **Hospital moment**: network hospitals by pincode (`network_hospitals` exists), cashless steps, estimated out-of-pocket.
4. **Real insurers by user share**: fully right for the insurers that hold most retail health policies first, then the long tail.

## Open owner decisions (blocking real data)

1. **Real data rule change.** AGENTS.md and AI.md allow synthetic data only; the FSS rights register denies every real source. The owner asked for real insurers, products and documents. Needs an ADR: real **public** insurer documents allowed in FSS storage (never in git, each source recorded in the rights register, FOR LEGAL REVIEW); real **schedules** (personal data) only on the owner's machine with consent; CI stays synthetic.
2. **Open-sourcing FSS**: licence, attribution and redistribution rights of public insurer documents (FOR LEGAL REVIEW), and a secret-clean history (gitleaks: 2 hits, both the documented fictional `local-sandbox-key`).
3. **Spend**: every live document costs a Sarvam OCR call; model wording costs more once enabled.
