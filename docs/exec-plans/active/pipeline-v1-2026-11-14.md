# Document pipeline v1 (2026-11-14, Squad B draft for the 19:40 debate with Squad A)

Owner goal (2026-11-14 evening): parse every public insurer PDF asynchronously and store the results on the server,
so the product never re-reads insurer wordings at question time. When a person uploads their own policy, the server
finds the insurer wording for that UIN in the store and builds the answer from both. No local-only data.
Spend: Sarvam allowed; a $5 Gemini credit for the model stage. Nothing else paid.

## 1. Where everything lives

| What | Store | Key | State |
| --- | --- | --- | --- |
| Insurer PDF bytes | R2 bucket `knowvia-insurance` | `<insurer>/<UIN or unassigned>/<product>__<doc_type>__<sha8>.pdf` | DONE: 4,317 PDFs |
| Text layer per PDF (pages, tables) | R2 | `artifacts/text-layer/v1/<sha2>/<sha>.json.gz` | RUNNING (`docs:extract-text`) |
| OCR of pages with no text | R2 | `artifacts/ocr/sarvam-v1/<sha2>/<sha>.json.gz` | TODO (stage 3) |
| Model extraction (facts per product) | R2 | `artifacts/extraction/<schema>/<sha2>/<sha>.json.gz` | TODO (stage 4, Gemini) |
| Rows: documents, document_artifacts, insurer_contacts, facts | Postgres | tables (FSS migrations 022, 023, ...) | LOCAL staging only |
| Row snapshots (rebuild any Postgres) | R2 | `manifests/<table>/latest.jsonl.gz` | BUILT (`docs:snapshot`) |

Artifacts are keyed by the PDF's sha256, so a rename of the readable PDF key (`docs:load --rekey`) never moves them.

**Blocker: no hosted Postgres for FSS yet.** Options, owner to pick: (a) Supabase FSS project (needs the owner's
Supabase login), (b) Cloudflare D1 (needs Cloudflare API access; this session was not allowed to run wrangler).
Until then the bucket is the system of record: every row is snapshotted to `manifests/` after each stage, and the
local Postgres is a rebuildable cache.

## 2. Stages (each idempotent per sha256 + schema version, resumable, wording first)

0. **Collect + tag** (done): raw PDFs, five tags (UIN, insurer, product, category, PDF), `extracted_unverified`.
1. **Store** (done): bytes to R2 under readable keys, rows in `documents`.
2. **Text layer** (free): pdfplumber in an isolated worker, pages + tables, `needs_ocr` page list.
3. **OCR** (Sarvam, allowed): only pages listed as `needs_ocr`, only for wordings/CIS of products that a user
   holds or that have no text at all. Budget cap per run; never whole documents that already have text.
4. **Model extraction** (Gemini, $5 cap): per product (UIN), the wording + CIS text, retrieval-trimmed to the
   pages that mention each fact family (waiting periods, room rent, co-pay, sub-limits, exclusions, sum insured,
   restore, no-claim bonus). Output: the FSS fact schema, each value with page and quote, `extracted_unverified`.
   Hard budget counter in the database before each call; stop at $4.50. Health wordings first.
5. **Serve**: FSS `GET /v1/products/by-uin/{uin}/export` reads stage 2-4 artifacts (not live PDF parsing).
   CoverSaath's existing reference import (`reference.import` job, `ida_wording` tier) pulls the export into the
   holding. The person's own PDF stays in CoverSaath (sealed, consent-gated); insurer data is public.

## 3. Rules carried over

- Deterministic code decides; model output is only `extracted_unverified`, `conflicting` or `unknown`.
- Public insurer data only in FSS stores; no household data ever goes to FSS or the bucket.
- Every artifact records `produced_by` and a schema version; a new version is a new artifact, never an overwrite.
- A stage never deletes an earlier stage's output.
