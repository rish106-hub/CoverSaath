# ADR 0036: Show model-extracted insurer facts as "not checked"

- Status: Proposed (2026-11-14). Owner decision taken; implementation follows the first extraction run. Not reviewed. Builds on ADR 0034 (FSS as the insurer tier). FOR LEGAL REVIEW: the display wording.

**Context.** FSS will extract insurer facts from public policy wordings with a model (FSS `docs/contracts/extraction-v1.md`, signed off 2026-11-14). Every such fact is `extracted_unverified`, with a page and verbatim quote. CoverSaath today drops any insurer fact that is not `independently_verified`: `parseFact` blanks its value, and `fss-fact-map.js` maps only `outcome === 'verified'`. Migration 049's pairing CHECK also allows `ida_wording` only with `reviewed_reference | conflicting | unknown`. So none of the extracted facts would ever reach a user. On 2026-11-14 the owner chose to show them, labelled "From the insurer's wording, not checked".

**Decision.**
1. **Status.** `ida_wording` gains `extracted_unverified`. `TIER_STATUSES.ida_wording` becomes `reviewed_reference | extracted_unverified | conflicting | unknown`. A new migration replaces `household_memory_facts_tier_status_check` the same way (expand-only, existing rows untouched).
2. **Quote end to end.** Today the quote is dropped on the way in: `parseEvidence` keeps no quote, and `fss-fact-map.js` and `fss-reference-facts.js` set `quote: null`. This ADR adds the quote along the whole path. FSS `versions.facts` evidence carries `quote` only when `quote_included` is `true`, and no `quote` field when it is `false` (the export shape, as in `scripts/fixtures/ida-export-v2-synthetic.json`). extraction-v1 requires a 12–200 character verbatim quote on every stated variant (enforced by `tools/golden-check.py` and the FSS validator); confirm the exporter sets `quote_included: true` for those before implementation. `parseEvidence` keeps the quote exactly as sent: a quote over 200 characters or holding a control character (other than a plain space) is rejected, so that evidence item has no quote. It is never trimmed or stripped, so what is shown stays verbatim. The reference evidence that `fss-fact-map` seals into `reference_ref_enc` keeps it, and the display reads it back from the sealed reference only.
3. **Parsing.** `parseFact` (integrations/insurance-data/schemas.js) keeps the value of a non-synthetic fact whose `verification_status` is `extracted_unverified` **only when at least one *parsed* evidence item has a page and a non-empty quote**, with `outcome: 'unchecked'`. The gate is on the parsed evidence, never on the raw array, so a fact whose evidence items all have `quote_included: false` (or a rejected quote) stays hidden. Test: such a fact is blanked. Everything else is unchanged: `verified` still needs `independently_verified` plus family coverage. The value is bounded by the same parsers.
4. **Mapping.** `fss-fact-map.js` maps `outcome: 'unchecked'` to an `ida_wording` row with status `extracted_unverified`, and `verified` to `reviewed_reference` as today. The evidence (page, quote) is sealed as now.
5. **Collate.** An `ida_wording` row with `extracted_unverified` is never the holding's decided value, and today's code has no path for it (`collateSlot` would call any own/insurer pair a conflict unless the insurer row is `reviewed_reference`; `resolveSlot` returns an insurer value only when it is `reviewed_reference`). Both get an explicit unchecked branch:
   - `collateSlot`: when an own-PDF row exists, an unchecked insurer row is dropped (not written) and raises no `own_vs_insurer` conflict; the own-PDF row is kept as is. The agree/conflict logic stays only for `reviewed_reference` insurer rows.
   - `resolveSlot`: order becomes `reviewed_reference` insurer > own PDF (`extracted_unverified`) > unchecked insurer > unknown. The new branch `productTerm && ida?.status === 'extracted_unverified'` returns status `extracted_unverified`, source tier `ida_wording`, `checkWithInsurer: true`. It is never promoted.
   - Tests: own value + unchecked insurer value → own wins, no conflict; unchecked insurer alone → `extracted_unverified` from `ida_wording`; reviewed insurer still beats both.
6. **Never a verdict.** The existing status filters stay and are named here so this change cannot widen rule inputs: chat drops every `status === 'extracted_unverified'` fact before procedure planning (`chat-v1-service.js`, the `relevant` filter for `procedure_planning` and the facts passed to `planProcedure`), whatever its tier. Rules (`insurance-rules`) and computed checks read only `reviewed_reference` and confirmed values. Pin tests: an `ida_wording` `extracted_unverified` row never reaches `planProcedure`, a computed check or a rule result. In chat, an unchecked insurer fact may be cited as a source only with its insurer page and quote. Today `context.places` holds own-PDF places only (`ownFactSources`), so `factEvidence` for an `ida_wording` fact would carry no page or quote and the guard would match only the formatted value. The chat context gains the insurer place: `fss-reference-facts.js` unseals `reference_ref_enc` and adds `{ page, quote }` for each `ida_wording` source id to `places`. `factEvidence` for an `ida_wording` fact uses that page and quote, never the formatted value as a stand-in; with no quote the fact is not cited (test). Then it shows as answer card `sources[].tier = 'ida_wording'`, `status = 'extracted_unverified'`, and the guard's checks apply. The card `verdict` stays `unknown`.
7. **Display.** The policy card and chat show "From the insurer's wording, not checked", with the page and the quote. The label is chosen from **tier and status together**, never status alone: today both `chat-answer.js` (`SOURCE[fact.status]`) and the model slot label in `chat-v1-service.js` would call an unchecked insurer fact "read from your policy document". Both get a `(sourceTier, status)` lookup with tests. The beta tile badge maps to `ida_wording` with an "unchecked" variant. Wording FOR LEGAL REVIEW.
8. **Erasure and retention.** The household rows (`household_memory_facts`, `ida_wording`, with the sealed evidence and quote) are erased with the holding, the document or a revocation, as now. `reference_cache` is public insurer data with no household, case or consent key (migration 033), so household erasure does not and cannot touch it. It keeps its own policy: entries expire by `stale_after` (the repository's fetch TTL defaults to 24 hours per migration 033; the reference import sets its own, `DEFAULT_IMPORT_TTL_DAYS` = 30 in `reference-data-import.js`), are replaced by the next import, and are removed by the `import-` rollback. No new store.

**Consequences.** Users see insurer terms for products where the policy itself is silent. That's the value of the extraction run. The risk is a wrong extracted value shown as insurer wording, contained by: the label, the quote shown with it, the extraction gate (≤ 2% false values on the golden set), the never-a-verdict rule, and the guard. A later independent review (FSS checker workflow) promotes a fact to `reviewed_reference` with no CoverSaath change.

**Alternatives rejected.**
- Keep dropping unverified insurer facts until reviewed: safe but slow, and nothing reaches users for months (owner rejected).
- Treat extracted facts as `reviewed_reference`: breaks the rule that a model never writes `reviewed_reference` (AI.md, migration 049).
