# ADR 0016: Structured logging (pino) and error reporting (Sentry)

Status: accepted for the prototype (synthetic data only). The log retention period is a draft for legal review.

## Context

The API wrote four ad-hoc `console.warn(JSON.stringify(...))` lines and nothing per request. There was no request correlation and no error reporting, and Node's default fatal-error handler prints the error message, which can hold a value (a driver message includes the offending row). The product is consent-first: a log or an error report is a disclosure channel, so it must carry no personal data.

## Decisions

**D1. Dependencies (measured need: production visibility before the first hosted run).** `pino` (structured JSON lines, built-in path redaction, synchronous stdout destination) and `@sentry/node` (error reporting). Nothing else; Grafana and OpenTelemetry are a later task (M2). `@sentry/node` is imported only when `SENTRY_DSN` is set.

**D2. Metadata only, enforced in layers.** (1) Callers cannot log free text: event names must match `^[a-z][a-z0-9_]*$`; the generic methods (`info`, `warn`, `error`, `debug`, `log`) keep only a fixed set of scalar keys (`errorCode`, `code`, `reason`, `signal`, `setting`, `host`, `exitCode`, `port`, `attempts`, `count`), each validated to a narrow shape, and drop every other key (message, detail, note, url, query, error objects, nested values), counting them in `droppedFields`; the request, failure, audit and provider helpers keep their own allowlists. `level`, `time`, `service` and `event` cannot be set by a caller. No path logs a person's name, so a name in a script the patterns cannot recognise (Devanagari) cannot reach a line. (2) Errors are logged as class name, machine code, HTTP status, the setting name of an "Invalid NAME." startup error and (for unexpected failures) up to six stack frames; never message, detail, cause, query or parameters. A frame is kept only if the whole line has the V8 frame shape, its file is reduced to a repo-relative path, and a frame that changes under scrubbing is dropped, so lines of a multi-line message are not frames. (3) pino `redact` paths remove body, headers, payload, prompt and text keys. (4) Every line is parsed and scrubbed again before it is written: keys that name sensitive data lose their value, and every string is Unicode-normalised (NFKC), pattern-scrubbed and then folded to printable ASCII (anything else becomes `?`). Patterns: PAN (also spaced, hyphenated or glued to letters), IFSC, vehicle registration, any run of nine or more digits in any script with up to three space, dot, hyphen or slash separators (Aadhaar, phone, card, account), dates of birth (`dd/mm/yyyy`, `dd-mm-yy`, `yyyy-mm-dd`, `15 Aug 1990`), anything shaped `name@host` (e-mail and ABHA addresses), bearer credentials and JWTs. Strings are scrubbed before they are cut to 500 characters. Detection is over-eager on purpose (an ISO date or a long number in a string is redacted); a false positive costs a redacted field. The `time` and `level` values pino writes are kept only in their exact expected shape.

**D3. Request correlation and routes.** Each request gets a server-generated id (`req_` plus 12 random bytes, base64url), returned as `X-Request-Id` and written on the request line, the failure line and the Sentry tag. A client-supplied id is ignored, so a caller cannot put its own text into every line. The request line is written when the response closes, so a request the client aborted is logged too (`aborted: true`, no status). The logged route shows only words from a closed set of known route words (`KNOWN_ROUTE_SEGMENTS`, kept in step with the routes file by a test); ids become `:id` and any other word `:x`.

**D4. Sentry off by default.** No DSN, no SDK load, no network. With a DSN: `sendDefaultPii:false`, no breadcrumbs, no tracing, no OpenTelemetry setup, no local variables, no default uncaught-exception hooks (the entry point logs and reports fatal errors itself through the sanitiser). Only a stand-in error carrying a trusted code and the sanitised frames is handed to the SDK, and `beforeSend` rebuilds the event from an allowlist (type, a message only if it is a trusted code, relative frames with no source lines, variables or absolute paths, `requestId` tag, request method) and drops user, request data, breadcrumbs, extras and server name. A code is trusted only if it is on a built-in list (plus the codes `server.js` passes from `src/contracts/error-codes.js`), is UPPER_SNAKE with an underscore and is unchanged by scrubbing; a PAN-shaped or name-shaped value is never trusted and any other code collapses to `UNEXPECTED_ERROR` in the event (the exact code stays in the log line with the same request id). Reported: a 500, or a 5xx that carries no application code. An expected 503 with a deliberate code (`PROVIDER_NOT_CONFIGURED`, `DATABASE_UNAVAILABLE`) is logged, not reported. The DSN is validated but never echoed.

**D5. Default logger is silent.** `createApiServer` takes `logger` and `errorReporter`; without them nothing is written, so tests and embedders stay quiet. Only the process entry point (`src/server/server.js`) builds the real logger from `LOG_LEVEL`.

**D6. Audit.** `AuditRepository` accepts an optional `onAudit` hook and calls it after each append with action, resource type, resource id, actor type, household and case id only. The audit payload and actor id are never logged. The hook fires when the append returns; if a caller's outer transaction later rolls back, the log line remains (it is operational visibility, not the audit record).

**D7. Supply chain.** `pino` brings 11 small packages of its own (MIT). `@sentry/node` 11.x is MIT; its tree also installs `@sentry/bundler-plugins` (build-time bundler plugins), the `sentry` command-line tool (FSL-1.1-Apache-2.0: free for internal use, restricts only competing products, converts to Apache-2.0 after two years; legal to confirm), `dotenv`, `glob`, `minimatch` and `oxc-parser` with a prebuilt native binding (optional, per platform), and `@opentelemetry/api`. None of these is imported at runtime: the server imports only `@sentry/node`, and only when `SENTRY_DSN` is set. No package in `package-lock.json` has an install script (`hasInstallScript` count is 0; the `prepare` scripts of `glob` and `minimatch` run only in their own repositories). A lighter option exists (`@sentry/core` with a hand-written transport) but it means maintaining client and transport code here; revisit if the installed size or the licence matters. Decision: accept `@sentry/node` for the prototype and re-check the tree at each upgrade.

## Consequences

- Rollback: unset `SENTRY_DSN` (reporting stops at once); set `LOG_LEVEL=silent` to stop logs; or revert this change (the old `console.warn` lines were operational events only and are replaced one for one).
- Single process: request ids are random, not sequential, so they work across machines. No log shipping or retention is configured here; the host (Fly) keeps stdout for a short window. Intended retention is 30 days, to be confirmed with legal. A sink that keeps logs longer needs its own review.
- Not covered: stdout/stderr of the PDF child processes (they emit JSON results to the parent, not logs), and Node warnings printed by the runtime. The Fly proxy keeps its own access log with URLs; query strings must not carry personal data (the API does not use any).
- Verification: `tests/logging-leak.test.mjs` pushes synthetic PAN, Aadhaar, phone, card and e-mail through the request, error, audit, provider and Sentry paths and fails if any appears.
