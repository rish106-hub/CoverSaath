# ADR 0039: Insurer tier in policy.md, an optional prose pass behind a guard, and insurer wording in chat v1

- Status: Proposed (2026-11-19). Built with this ADR (plan step C5, owner: "fold chat v1 into C5"). Not reviewed: needs an independent read-only review (AI.md: AI and trust change). Builds on ADR 0032 (memory document), 0036 (unchecked insurer facts), 0037 (FSS handoff, pack), 0038 (chat router) and ADR 0012 D9 (bounded passages). ADR 0039 was free; no renumbering.
- FOR LEGAL REVIEW: every reader-facing label and notice named below.

**Context.** The owner's memory document (`memory-document.js`, ADR 0032) is rendered on demand from sealed rows. It already resolves each slot with `resolveSlot` (reviewed insurer > own PDF > unchecked insurer > unknown) and cites `[insurer_wording, p.N]`, but it does not say plainly which terms come only from the insurer, and an insurer fact with no quote shows as a line anyway. Chat v1 cites unchecked insurer facts (ADR 0036 D6) but cannot cite insurer wording passages, which C4 added to the passages route and chat v0 only. The owner wants a readable policy.md that fills the gaps in the person's own PDF from the insurer's wording, always labelled, and optionally in plainer words.

**Decision.**

1. **Insurer-tier lines in policy.md.** A fact whose resolved source tier is `ida_wording` renders as `- <question> <value> (From the insurer's wording, not checked) Quote: "<=160 chars>" [insurer_wording, p.N]`. The label is the canonical `INSURER_UNCHECKED_LABEL` through `factSourceLabel` (tier and status together, ADR 0036 D7), one string shared with chat and the beta tile, not a second shorthand. A reviewed insurer fact keeps `(insurer wording)`. The quote is the sealed reference quote, cut at 160 characters with an ellipsis; the citation page is the quote's page. Own-PDF lines, ordering and wording do not change: verified once by a diff against the base render (commit d0de335) on the memory-document test world, where the only difference is the new fixed section. The existing memory-document tests pin the own-PDF lines.
2. **Block "Insurer terms your document doesn't state".** A new section holds each resolved fact whose source tier is `ida_wording` and that has no own-PDF source (the own-PDF slot is unknown). Such a fact is moved out of its topic section into this block, never listed twice. The block is a fixed section: with nothing to show it holds `- None recorded. [unknown]`. This adds one heading to the fixed section list (`MEMORY_DOCUMENT_SECTIONS`): the beta renderer (plan C7) must accept it. Where an own-PDF reading exists, collate has already dropped the unchecked insurer row (ADR 0036 D5), so own facts win; a reviewed insurer value that agrees with the own reading cites both and stays in its topic section.
3. **Never shown.** A fact `shown: false` is dropped in the FSS parse and a `stated_nil` value maps to nothing (`fss-fact-map.js`); memory rows carry neither field, so policy.md cannot show them. Pin tests go through the pack parse and map path. An unchecked insurer row with no quote is not a line (chat does not cite it either, ADR 0036 D6): its label goes to Open questions.
4. **Open questions.** Terms neither source holds (no memory row, or an insurer row without a quote) are listed as `- <question> [unknown]`, as today.
5. **Prose pass (optional, off).** Behind `POLICY_DOC_PROSE_ENABLED`, off unless exactly `true`, and only with a ready chat model route (`CHAT_MODEL_ENABLED`). A separate method, `renderWithProse`, serves it; `render()` stays deterministic and is what the route serves while the flag is off. The model rewrites the wording of fact sentences only:
   - Code owns everything fixed. Each fact line is split into an id, a sentence (the question and the value), and a fixed tail (tier label, quote, citation) that code re-appends unchanged. The model sees and returns sentences only, so a quote, a page, a label or a status cannot change by construction.
   - Data minimisation. Only fact lines of the sections Cover and limits, Waiting periods, Exclusions and the insurer block go to the model, and only for `product_term` facts: a `personal_value` (seller name, code and registration, member data) can carry an identifier and stays deterministic, as do the Open questions. Policy (names, UIN), People covered, Declared conditions (health declarations), Premiums and dues and Conflicts are never sent and stay deterministic. The text goes through the household privacy gate and the per-household budget like chat; names are tokenised and restored.
   - New gateway task `policy_doc_prose` (payload `{ lines: [{ line_id, text }] }`, output `{ status, lines: [{ line_id, text }] }`), registered like the other gateway tasks (authority `propose`, routing as chat, data-purpose slots, prompt pack, schema). Model output is only `extracted_unverified` or `unknown`; it never writes a row.
6. **Line-by-line guard.** Each returned line is checked against its own source sentence, using the chat answer guard's primitives (`number_grounded`, `no_advice`, `no_outcome_promise`, `no_identifier_echo`, `contact_trusted`), plus "no new facts": same id set and count, every number of the output is a number of the source, no `[`, `]` or quote mark, negations in the source are kept, every content word of the output occurs in the source or in a short list of function words, and a length cap. `quote_exact` holds by construction (item 5), and a test also proves that the quote in the served text is the stored quote. Any failed line fails the whole pass.
7. **Fallback.** A flag off, a missing or unavailable provider, no current consent, a budget refusal, a timeout (an abort signal for the whole pass, 20 seconds by default, `POLICY_DOC_PROSE_TIMEOUT_MS` 50 to 60000), a malformed or guard-failing output, or consent withdrawn while the call ran, serves the deterministic render. The reader is told which text they got by one fixed line in the prose version ("Wording simplified by a model; values, quotes and pages are set by code. (Draft wording, FOR LEGAL REVIEW.)"). A withdrawn document grant is not a fallback: it is the existing 403 `CONSENT_REQUIRED`.
8. **Consent and model.** The call needs the household's current exact chat grant (purpose `coverage_reconstruction`, insurance_question, recipient = the routed provider), resolved server side, re-checked right before dispatch (`authorize`), and re-checked once more after the model returns and before the text is served (the equivalent of the commit re-check: nothing is stored, so the "commit" is the serve). The provider is not approved yet: tests use a local stub and never a live call; with no key the route answers a typed unavailable and the deterministic render is served. Open question: whether the prose pass needs its own consent scope instead of the chat scope. FOR LEGAL REVIEW.
9. **Chat v1 and insurer wording.** Insurer facts already reach a chat card with the insurer's page and quote (ADR 0036 D6). This ADR adds insurer wording passages: when the person's own documents do not answer (the case where chat now says the documents do not say), and the holding's linked FSS version has cached pack pages with a line that matches the question, the deterministic answer cites that line with page and quote, labelled "From the insurer's wording, not checked" and a notice that it is general product text for the linked plan, not read from the person's documents and not a decision. Rules:
   - Card tier stays `ida_wording` (the card contract's value; an unknown tier would fall back to `own_pdf` and mislabel insurer text, the C4 review bug), status `extracted_unverified`. The streamed `sources` list carries these as kind `insurer_wording`, never kind `wording` with a document id.
   - The quote is a raw line of the cached pack text, at most 160 characters, so `quote_exact` holds against the pack text. A line that holds a contact value or an identifier label, or reads as schedule content, is dropped.
   - Deterministic only: insurer passage text is never sent to a model, never embedded, never put into `memory_chunks` (migration 053 keeps `own_pdf` only), and never in the trace's chunk ids.
   - Never a verdict: insurer passages and unchecked insurer facts never reach `planProcedure` or the rules (ADR 0036 D6 allowlist: only `reviewed_reference` and `user_confirmed`). Procedure questions do not read insurer passages.
   - Owner only (`mayReadFacts`), the holding's document must still be readable, household scoped through `holding_fss_links`.
10. **Erasure.** Nothing new is stored: policy.md and the prose are rendered and served, never cached; no migration, no table. The pack pages and facts are in `reference_cache` (public, unkeyed, ADR 0036 D8); the link and the `ida_wording` rows go with the holding, the document or a revocation. The model call leaves only its `provider_calls` row (counts and a digest, as chat). Tests dump the tables after a prose run and a chat turn and look for the marker text, and check revocation.

11. **Stored content.** No new store, but a chat v1 turn that cites insurer wording stores its answer text, which now holds a public insurer quote, in the existing sealed chat exchange store with its existing erasure path.

**Consequences.** The owner sees, in one place and in order, what their own document says, what only the insurer's wording says (marked not checked, with its page and quote) and what nobody says. The prose pass can make wording friendlier at the cost of a model call per document view; it can never change a number, a quote, a label or a page, and any doubt serves the plain version. The risk is a model sentence that is wrong in a way the guard cannot see (a changed meaning with the same words). Containment: the sentence keeps its fixed tail, content words must come from the source, negations are kept, and the flag is off until a provider is approved and reviewed.

**Alternatives rejected.**
- Let the model write whole paragraphs from the markdown: no way to guard a quote, label or page line by line.
- Cache the prose: needs a seal, an erasure path and tests for no gain; a render is cheap and the model call is opt-in.
- Add every insurer fact to the topic sections as well as the block: duplicates, and the reader cannot tell the gap apart.
- Send the whole markdown: declared health conditions and names would leave for an unapproved provider.
- Fit the prose into `chat_answer`: its instructions, schema and certainty checks answer questions; abusing them is worse than one small task.

**Verification.** `tests/policy-md-insurer-tier.test.mjs`: render with insurer lines, the block and open questions; `shown` and `stated_nil` through the pack path; own wins; reviewed insurer agrees with own; a personal value never reaches the prompt; prose flag off is deterministic; guard failure falls back; consent revoked mid-pass falls back with nothing stored; chat v1 insurer passage card with label, page and tier; no "your documents" for insurer text; rules never see insurer facts; another household denied; revocation empties everything.
