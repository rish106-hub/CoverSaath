# Security policy

## Supported versions

Only the `main` branch is supported. Security fixes land on `main`; there are no maintained release branches.

## Reporting a vulnerability

Please report vulnerabilities privately. Do not open a public issue or pull request that describes an unpatched vulnerability.

Use GitHub private vulnerability reporting for this repository:

1. Open the repository's **Security** tab.
2. Choose **Report a vulnerability** (Security Advisories).
3. Describe the issue, the affected component or file, steps to reproduce, and the impact you expect.

If the **Report a vulnerability** option is not visible, private reporting has not been enabled yet. Open a public issue that asks the maintainers to enable it and contains no technical details of the vulnerability.

## What to include

- Affected commit or branch.
- A minimal reproduction using synthetic data only.
- No real personal data, medical records, policy documents, credentials, or API keys. Redact or replace them.

## Scope notes

CoverSaath handles insurance-related documents and consent decisions. Reports about consent enforcement, redaction or minimisation gaps, cross-household data exposure, prompt injection that reaches a privileged action, and secret leakage are treated as high priority.

## Handling

Maintainers will acknowledge a report, assess severity, and coordinate a fix and disclosure through the advisory. No fixed response times are promised at this stage.
